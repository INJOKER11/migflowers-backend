# Приглашение Верочки: отдельный endpoint Laravel

`POST /api/vera-rsvp`. По умолчанию выключен. Существующий сервис Telegram магазина,
его настройки, CORS, таблицы и маршруты не изменены. Единственное дополнение в
существующем файле — регистрация `VeraRsvpServiceProvider` в `bootstrap/providers.php`.

## Включение позже на сервере

Добавить в окружение сервера (значения ниже — примеры, не настоящие секреты):

```dotenv
VERA_RSVP_ENABLED=true
VERA_RSVP_BOT_TOKEN=replace-with-bot-token
VERA_RSVP_CHAT_ID=replace-with-your-chat-id
VERA_RSVP_INVITATION_KEY=replace-with-a-random-private-key-at-least-32-characters
VERA_RSVP_ALLOWED_ORIGINS=https://your-invitation.vercel.app
VERA_RSVP_CACHE_STORE=file
```

Ключ приглашения можно сгенерировать через `php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'`.
Он отдельный от токена Telegram. Передать его только приватному приглашению, например
через фрагмент ссылки, который клиент прочитает и передаст в `X-Vera-Invitation`.
Не встраивать токен Telegram в сайт. Доступ к ссылке/ключу позволяет отправлять ответы:
это приватное приглашение, а не удостоверение личности Верочки.

Сначала открыть своего бота в Telegram и нажать Start. `CHAT_ID` — получатель сообщения,
он никогда не принимается из запроса. Получатель и токен намеренно не наследуются от магазина.

После добавления настроек обновить конфигурационный кэш штатным способом деплоя проекта
(`php artisan config:cache`); при использовании кэша маршрутов пересобрать и его
(`php artisan route:cache`). Эти команды сейчас не запускались.

`ALLOWED_ORIGINS` — точные origins без путей и завершающего `/`, несколько через запятую.
Для локальной проверки при необходимости добавить `http://127.0.0.1:4317`.
CORS действует только на `api/vera-rsvp`; разрешения магазина не расширяются.
Серверные запросы без `Origin` разрешены, но всегда требуют ключ приглашения.

`file` не требует базы или миграций. У PHP должны быть права записи в штатный кэш
`storage/framework/cache/data`. Для нескольких инстансов нужен общий cache store
(например, уже настроенный Redis). Иначе дедупликация и лимиты будут локальными.

## Контракт для сайта

Заголовки:

```http
Content-Type: application/json
Accept: application/json
X-Vera-Invitation: <приватный ключ приглашения>
```

Тело запроса (дата ниже только пример; при отправке нужен будущий день):

```json
{
  "request_id": "84c57ad9-725a-45ec-ac8f-6d98ee1eecaf",
  "activities": ["Посмотреть «Беременна в 16»", "Просто поговорить"],
  "idea": "Запасайся вкусняшками",
  "date": "2026-09-24",
  "time": "20:00",
  "timezone": "Europe/Warsaw"
}
```

`activities` — массив из 0–4 разных пунктов: `Посмотреть Инстаграм`,
`Посмотреть «Беременна в 16»`, `Просто поговорить`, `Поиграть во что-то`.
`idea` — до 180 символов. `date` и `time` необязательны: можно опустить или передать `null`.
`timezone` обязателен; передавать `Intl.DateTimeFormat().resolvedOptions().timeZone`.
Прошедшие даты/время и несуществующее местное время при переводе часов отклоняются.

Клиент создаёт `crypto.randomUUID()` один раз для одного подтверждения и повторяет
тот же `request_id` с тем же содержимым при повторной попытке. На время запроса
блокирует кнопку. При изменении плана создаёт новый ID. Не генерировать новый ID
автоматически после сетевой ошибки — сообщение могло уже дойти.

Ответы:

- `200 {"ok":true,"duplicate":false}` — Telegram подтвердил отправку; показывать букет.
- `200 {"ok":true,"duplicate":true}` — этот запрос уже успешно обработан, повторной отправки нет.
- `403 invalid_invitation / origin_not_allowed` — неверный ключ или origin.
- `413 payload_too_large` — тело больше 8 КБ.
- `422 validation_failed / date_in_past / time_invalid_or_in_past` — исправить поля.
- `409 in_progress` — предыдущая обработка ещё идёт; повторить с тем же ID после `Retry-After`.
- `409 request_id_conflict` — этот ID использован для другого содержимого.
- `409 delivery_unknown` — доставка не подтверждена (например, тайм-аут). Не показывать
  успех и не отправлять с новым ID автоматически: проверить Telegram вручную.
- `429 rate_limited` — подождать указанное в `Retry-After` число секунд.
- `502 telegram_unavailable` — Telegram явно вернул ошибку; допустима повторная попытка с тем же ID.
- `503 not_configured / temporarily_unavailable` — не включено, не заполнены настройки или недоступен кэш.

Лимиты: 5 запросов в минуту на IP, до 10 попыток отправки в час на ключ приглашения.
Записи дедупликации живут 24 часа. Telegram не поддерживает ключи идемпотентности:
абсолютная гарантия «ровно один раз» невозможна при сбоях. Неопределённые результаты
сохраняются, чтобы не дублировать сообщения автоматическими повторами.

Сайт пока не подключён: для этого нужны реальный URL бэкенда и способ передачи
ключа приватному приглашению. Секреты в локальный проект не добавлялись.
Реальные сообщения не отправлялись. Тесты не добавлялись по просьбе пользователя.

## Откат

Удалить только строку `App\Providers\VeraRsvpServiceProvider::class,` из
`bootstrap/providers.php`, затем эти добавленные файлы:

```text
app/Providers/VeraRsvpServiceProvider.php
app/Http/Controllers/Api/VeraRsvpController.php
app/Http/Middleware/VeraRsvpCors.php
routes/vera_rsvp.php
config/vera_rsvp.php
VERA_RSVP.md
```

Если изменение к тому моменту было задеплоено, убрать `VERA_RSVP_*` из окружения и
пересобрать кэши конфигурации/маршрутов штатным способом. Не очищать общий кэш магазина:
ключи `vera-rsvp:*` истекут сами. Миграций или изменений существующих данных нет.
